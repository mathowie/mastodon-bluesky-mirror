# Threads Mirroring Implementation Plan

> **For agentic workers:** Use the test-first workflow and independent final code review. Implement the tasks below continuously within the authorized feature scope.

**Goal:** Mirror eligible Mastodon posts to Threads alongside Bluesky.

**Architecture:** Share source polling, but keep each destination's records,
failures and publication state independent. Add a Threads API client and private
renewable token store; use container IDs and conservative recovery for writes.

**Tech Stack:** Python 3.11, requests, FastAPI, SQLAlchemy, SQLite, existing Docker image.

**Spec:** `docs/superpowers/specs/2026-10-30-threads.md`.

## Global constraints

- Disabled by default, future public posts only; preserve all Bluesky state.
- Freeze and checkpoint before remote writes. Never retry an ambiguous publish.
- Private token file is atomic and mode 0600. No real identifiers in fixtures.
- The NAS database is accessed only inside its container, never through SMB.

## Review focus

- A write succeeds remotely but its response/checkpoint is lost: no duplicate.
- An account/token changes while jobs exist: never publish to the wrong account.
- One destination is unavailable: the other continues and retries independently.
- Photos process asynchronously, expire or fail: never claim text-only success.
- Upgrades and restarts preserve activation times, completed parts and credentials.

## Task 1: Client, authentication and setup (independent implementation)

Files: `app/clients/threads.py`, `app/core/threads_auth.py`,
`app/threads_setup.py`, `tests/test_threads_client.py`, `tests/test_threads_auth.py`.

Interfaces: `ThreadsClient(config=None, session=None)` exposes `account_id`,
`create_container(payload)->str`, `container_status(id)->dict`,
`publish_container(id)->str`, `media_details(id)->dict`, and `connection_status()->dict`.
`ThreadsAPIError` exposes `http_status`, `retry_after` and `transient`.
`ThreadsTransportError` identifies uncertain network responses. No implicit
publication retries. Tests substitute only HTTP transport, never use live tokens.
